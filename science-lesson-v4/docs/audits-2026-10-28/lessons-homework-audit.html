#1Bug riskHomeworkAbout 45 minutes

Protect the "never repeat a question" record

Why it matters: one damaged file and every class could quietly start getting questions they have already had.

The list of which exam questions each class has already seen (used by homework, exam practice, Do Nows and the board exam question) is kept in one file on the home PC. It is not in the project's history, so there is no backup. If that file is ever unreadable (a half-saved write, a sync clash), the homework tools treat it as empty, carry on, and save over it with only the newest entries. Nothing warns you. Fix: refuse to save if the file could not be read, and keep a dated copy each time it changes.

For Claude: exam-usage.json is untracked; readJson() swallows parse errors in homework-forms.js write(), test-paper.js (~line 1081), exam-pick recordUse, extension-pick. Fail loudly on read error; write via temp file then rename; keep a rolling backup.

#2BugA levelAbout 1 hour

A-level lessons record the wrong Drive address

Why it matters: 12C and 13D lose the phone MCQ voter questions, and pushes to the school Drive would aim at a folder that does not exist.

Every built lesson leaves a small note of where it lives on Drive. For A level it writes "Year 13, Physics, Chapter 20...", but A-level folders have no Physics level and sit inside Module folders (Hubble's Law shows this). The uploader itself finds the right chapter, so the files land correctly. But the planner uses the note to attach each lesson's MCQs for the phone voter, so A-level lessons silently get none. The school push uses the same wrong address.

For Claude: builder/17-main.js writes .path.txt and .manifest.json "folder" as Year/Subject/Macrotopic; reuse the uploader's chapter-by-number lookup for Year 12/13. planner-catalogue.js lessonMcqs() keys on that path.

#4Support sheetsBugAbout 1 hour

Starters on the support sheet; no free working on the standard sheet

Why it matters: the pupils who need the help don't get it, and the pupils who should be stretched do.

Two open backlog items from 3 October, both still in the code. (1) On a 5+ mark long answer, the support sheet swaps your own sentence starters for the generic "What changes? Why? What does this mean?" lines, while the standard sheet keeps your starters. (2) For a calculation marked as a new method, the standard sheet pre-fills the Given, Unknown, Equation and Substitute boxes even on Mastering questions, which gives the working away. Research on fading help (expertise reversal) says the stronger pupils should get the blank version. Fix: starters go to the support sheet, and pre-filled boxes only appear there.

For Claude: builder/16-worksheet.js, the B4 "To answer this question" branch blocks q.starters on mode 'developing'; the 'backward-fade' GUESS mode pre-fills on the standard sheet for new_procedure. Add fixture assertions for both.
